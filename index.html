Publiqué esta página web utilizando GitHub Actions y Surge.sh. Configuré un flujo de trabajo que permite desplegar automáticamente los cambios cada vez que se realiza un push al repositorio de GitHub, sin tener que publicar los archivos manualmente.

Tecnologías utilizadas

Herramientas que permiten alojar el código, automatizar la publicación y recibir notificaciones.

🌐

HTML y CSS

HTML estructura el contenido de la página y CSS permite crear el diseño, los colores, las tarjetas y las animaciones.

🐙

GitHub

Plataforma utilizada para guardar el código fuente y registrar los cambios realizados al proyecto.

⚙️

GitHub Actions

Ejecuta automáticamente el flujo de trabajo cuando se envían cambios a la rama principal del repositorio.

🚀

Surge.sh

Servicio de alojamiento utilizado para publicar la página y obtener una dirección web pública.

🔐

GitHub Secrets

Permite almacenar el token de Surge de forma confidencial para utilizarlo durante el despliegue.

🔔

ntfy

Servicio utilizado para enviar notificaciones sobre el resultado de la automatización.

¿Cómo funciona la automatización?

El proceso conecta el repositorio de GitHub con el servicio de publicación.

1
Modificar Actualizo el código HTML.
2
Hacer push Envío los cambios a GitHub.
3
Desplegar Actions ejecuta el workflow y publica en Surge.
4
Notificar ntfy recibe el resultado del proceso.

Proceso de implementación

Pasos utilizados para preparar el proyecto y configurar el despliegue continuo.

1

Crear el repositorio en GitHub

Creé un repositorio para almacenar los archivos del proyecto. Agregué el archivo index.html con el contenido y el diseño de la página.

  • Crear el repositorio.
  • Agregar el archivo index.html.
  • Guardar los cambios mediante un commit.
2

Preparar el sitio en Surge.sh

Seleccioné Surge.sh como servicio de alojamiento para publicar la página. Necesité autenticarme y elegir un dominio disponible y autorizado.

3

Guardar el token como secreto

En la configuración del repositorio guardé el token de Surge con el nombre SURGE_TOKEN. Así, el workflow puede utilizarlo sin incluir el valor directamente en el código.

  • Abrir Settings en el repositorio.
  • Entrar en Secrets and variables → Actions.
  • Crear el secreto SURGE_TOKEN.
4

Configurar GitHub Actions

Creé el archivo .github/workflows/main.yml. Allí definí los pasos para obtener el código, preparar Node.js, instalar Surge y publicar la página cuando se envían cambios a la rama main.

5

Integrar las notificaciones con ntfy

Añadí pasos al workflow para enviar una notificación al tema devops-itla cuando el despliegue termina correctamente o cuando ocurre un fallo.

Tema de notificaciones: https://ntfy.sh/devops-itla

6

Probar el despliegue automático

Envié cambios al repositorio y revisé la pestaña Actions para comprobar el resultado del workflow. Después, verifiqué que la página publicada mostrara la versión actualizada.

Configuración del workflow

Ejemplo del archivo YAML que automatiza la publicación y envía notificaciones mediante ntfy.

Archivo: .github/workflows/main.yml 

name: Despliegue automatico a Surge

on:
  push:
    branches:
      - main
  workflow_dispatch:

jobs:
  deploy:
    runs-on: ubuntu-latest

    steps:
      - name: Descargar codigo
        uses: actions/checkout@v4

      - name: Configurar Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 22

      - name: Instalar Surge
        run: npm install --global surge

      - name: Publicar pagina web
        env:
          SURGE_TOKEN: ${{ secrets.SURGE_TOKEN }}
        run: surge ./ TU-DOMINIO.surge.sh

      - name: Notificar despliegue exitoso
        if: success()
        run: |
          curl --fail --silent --show-error \
            -H "Title: Despliegue exitoso" \
            -H "Tags: white_check_mark,rocket" \
            -d "La pagina web se publico correctamente en Surge.sh." \
            https://ntfy.sh/devops-itla

      - name: Notificar fallo del despliegue
        if: failure()
        run: |
          curl --fail --silent --show-error \
            -H "Title: Fallo en el despliegue" \
            -H "Tags: warning" \
            -d "El despliegue fallo. Revisa GitHub Actions." \
            https://ntfy.sh/devops-itla
Importante: sustituye TU-DOMINIO.surge.sh por el dominio real que tengas autorizado en Surge. También debes crear el secreto SURGE_TOKEN en GitHub. Nunca escribas tu token directamente en este archivo.

¿Qué hace cada parte?

Evento push

Inicia el workflow cuando se envían cambios a la rama main.

Publicación automática

Instala Surge y publica el contenido del repositorio en el dominio elegido.

Notificaciones

Envía mensajes diferentes a ntfy según el resultado de los pasos del despliegue.

El tema de ntfy es público si no has configurado controles adicionales. No envíes contraseñas, tokens ni información confidencial a través de él.
🎉

Resultado del proyecto

El objetivo es tener una página web alojada en Surge.sh que se actualice automáticamente cuando se envían nuevos cambios al repositorio de GitHub. GitHub Actions ejecuta el proceso de publicación y ntfy permite recibir notificaciones sobre el resultado, sin tener que cargar los archivos manualmente en el servicio de alojamiento.
